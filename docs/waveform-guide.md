# 怎么看仿真波形

跑 `scripts/run_sim_wave.tcl`，会一次把 14 个信号放进波形窗，分成三组。

> 为什么必须用这个脚本：xsim 只记录**开跑那一刻已在波形窗里的信号**。
> 点 "Run Simulation" 再往窗里拖内部信号，那些行永远是空的——不是采不到，是没开记录。

---

## 1 信号分组

| 组 | 信号 | 看什么 |
|---|---|---|
| **① CLK / FRAME** | `clk2`、`rst_n`、`u/fend`、`u/wr_ok` | 帧节拍。`fend` 是帧边界脉冲；`wr_ok` 恒为 1 是连续捕获的直接证据 |
| **② ONE ANALYSIS** | `u/ds_start`、`u/ds_busy`、`u/u_ds/pa_done`、`u/u_ds/pb_busy`、`D` | 一次分析的五段。`ds_busy` 的宽度就是下游占用时间 |
| **③ RESULT** | `LAT`、`L`、`R`、`BW`、`DC` | 锁存下来的结果：延迟、左边界、右边界、带宽、跨直流标志 |

---

## 2 三个必看的位置

### 帧节拍：`fend` 与 `wr_ok`

行为仿真的 `clk2` 是 10 ns 一个周期（板上是 8 ns，125 MHz），所以一帧在仿真里是 **10.24 µs**
（1024 个 clk2），板上是 **8.192 µs**。看波形时按 10.24 µs 认帧，别拿 8.192 去量。

`wr_ok` 必须**一直是 1**。它不是"写完拉低等分析"——这一版是连续捕获，写口始终开着，
忙不过来时读侧整帧跳过（丢帧式，不是背压式）。如果看到 `wr_ok` 掉了，说明跑的不是这一版 RTL。

### 一次分析的五段：从 `ds_start` 到 `LAT` 更新

光标放到 **52.6 µs**，能看到 `fend` 与 `ds_start` 的固定相位关系。然后向右拉到 **63.7 µs**，
这一段是 `ds_busy` / `pb_busy` 的活动区。要看的是：

- `ds_start` 距上一帧 `fend` 有固定几拍——这 3 拍就是"帧边界 → ds_start"同步与 bank 选择；
- `pa_done` 在一个固定的拍数后出现（pass A 每帧固定 586 拍，与数据无关）；
- `pb_busy` 的宽度**随向量变**（pass B 走查是数据相关的，最坏 517 拍）。

这三条的相对关系就是 `max(PA, PB) ≤ 1024` 的现场证据：只要两者都落在一帧内，N=1 成立。

### 重叠：`pb_busy` 与下一帧的 `pa_done`

这是整个"占空比 100%"的关键画面：**pass B(k) 与 pass A(k+1) 重叠**。
所以稳态吞吐由 `max(PA, PB)` 决定，而不是两者相加。

如果 `pb_busy` 结束后 `pa_done` 才开始，说明跑的是改版前的乒乓调度（N≥2），不是本版。

## 3 结果组怎么读

| 信号 | 含义 | 参考值（满带向量） |
|---|---|---|
| `LAT` | 分析处理时间（拍数） | 2128 拍 = 17.024 µs；结构上界 2132 |
| `L` / `R` | 带宽左 / 右边界（bin） | 0 / 8191（满带 1 GHz） |
| `BW` | 带宽（bin） | 8192 |
| `DC` | 跨直流标志（R < L 时置位） | 0（满带不跨界）；跨直流向量为 1 |

`BW × 122.070 kHz` 就是绝对带宽。满带 8192 × 122.070 kHz = 1000 MHz。
单音向量 `BW = 256`，正是 256 bin 平滑窗的宽度——**读数由窗宽决定，不是信号带宽**，这一点必须讲清楚。

## 4 末态判据

```
TB_END ndone=8 nwv=20714 nwr=12292 nfend=11 assert_fail=0
LAT cyc=2128 ns=17024
```

`assert_fail=0` 是硬条件；`ndone=8` 表示 8 次分析完成；`nwv` 是写谱有效拍数、`nwr` 是其中
`wr_ok` 为高的拍数，`nfend` 是帧边界个数。tb 在每一拍同时校验两件事——bin 轴是否按
`k0 = bitrev11(slot)` 单调推进、写地址 `{lane, waddr[8:0]}` 是否与 `kd3` 解码一致——任一条不符
`assert_fail` 就加一。所以 `assert_fail=0` 不是"没触发断言"这种宽松条件，而是逐拍核过索引。
这三个数对不上就不要往下读结果。

## 5 常见误读

| 现象 | 不是这个原因 | 真正的原因 |
|---|---|---|
| 内部信号全空 | 信号被优化掉了 | 开跑时没在波形窗里 → 用 `run_sim_wave.tcl` |
| 谱全 0 | RTL 有 bug | `$readmemh` 没找到文件，ROM 全 0（见 `reproduce.md` 坑 ①） |
| `BW` 与预期差几十个 bin | 合并级索引错 | 先跑 `sim/scan7.py` 的 8 点扫描，看偏差是否随 bin 跳变 |
| 报文全乱码 | UART 时序 | `CLK2_FREQ_MHZ` 没设成 125（工程级 define，不是参数） |
